# Methods

## Architecture: HRNet-W32

I chose **HRNet-W32**, the wider variant of HRNet, for pose estimation. HRNet is uniquely suited because it maintains high-resolution feature representations throughout the network — enabling precise keypoint detection even in challenging environments like underwater.

Unlike conventional CNNs that down-sample and later recover high-resolution representations, HRNet **maintains high-resolution feature maps** throughout by connecting multiple resolution subnetworks **in parallel**.

## Architecture Components

### Sequential Multi-Resolution Subnetwork
Connects high to low resolution subnetworks, where each subnetwork (stage) consists of convolutions followed by a down-sampling layer to reduce resolution by half. This is the conventional CNN pattern that HRNet starts with.

### Parallel Multi-Resolution Subnetworks
This is HRNet's signature contribution. Instead of sequential stages, **high-to-low resolution subnetworks are added in parallel**. Each branch processes the input at a different resolution simultaneously.

The resolutions for parallel subnetworks at each later stage include:
- The resolutions from the previous stage
- An additional lower resolution

So the network grows in parallel breadth as depth increases.

### Repeated Multi-Scale Fusion
The most important architectural piece. An **exchange unit** allows parallel subnetworks to repeatedly share information with each other.

Each stage is divided into multiple **exchange blocks**:
- Each block consists of parallel convolution units AND an exchange unit
- The exchange unit performs upsampling or downsampling as needed to align features across resolutions
- After exchange, parallel branches continue processing with enriched representations

This repeated information exchange is what gives HRNet its power. Information flows continuously between high-resolution and low-resolution streams, not just at the end.

### Heatmap Estimation
The final layer regresses **heatmaps** directly from the high-resolution representation output by the final exchange unit.

- Each pixel indicates the likelihood of a keypoint being present at that location
- **MSE loss** compares predicted heatmaps to target heatmaps
- Target heatmaps are generated by applying **2D Gaussian functions** centered on ground truth keypoint locations

## Network Instantiation Details

The network has **four stages with four parallel subnetworks**. As we move through stages, resolution gradually decreases by half while channel width increases double.

### Stage 1
- Contains **4 residual units**
- Each unit is formed by a bottleneck with width 64
- Followed by one 3×3 convolution that reduces feature map width

### Stage 2
- Contains **1 exchange block**

### Stage 3
- Contains **4 exchange blocks**

### Stage 4
- Contains **3 exchange blocks**

### Each Exchange Block
- 4 residual units
- Each unit has two 3×3 convolutions per resolution
- Plus one exchange unit operating across resolutions

The final layer outputs a set of heatmaps corresponding to the keypoints — one heatmap per keypoint, each pixel a confidence score.

## Data Collection and Preprocessing

### Source
Video footage was collected from the **University of South Carolina swim team during practice sessions**, focusing exclusively on underwater strokes to build a domain-specific dataset.

### Annotation
Frames were extracted and annotated in **COCO format**, which includes visibility flags to account for occlusions:

| Visibility Value | Meaning |
|------------------|---------|
| 0 | Not in frame |
| 1 | In frame but occluded |
| 2 | In frame and visible |

This three-state visibility labeling is critical. It lets the model distinguish "this joint isn't here" from "this joint is here but I can't see it" — two very different cases that should be handled differently in the loss.

### Data Augmentation
To enhance robustness given the limited dataset size:
- **Horizontal flipping** — generates left/right symmetry samples
- **Random rotation** — exposes the model to varied body orientations
- **Translation** — handles different positions within the frame

These augmentations roughly multiply the effective dataset size and help generalization.

## Training Setup

| Parameter | Value |
|-----------|-------|
| Optimizer | Adam |
| Learning rate | 1e-3 |
| Batch size | 8 frames |
| Epochs | 100 |
| Loss | MSE on heatmaps |
| Loss weighting | Visibility-weighted |

### Visibility-Weighted Loss
The visibility annotations dynamically weight the loss:
- Visible keypoints (vis=2) contribute fully
- Occluded keypoints (vis=1) contribute reduced weight
- Out-of-frame keypoints (vis=0) contribute nothing

This reduces the impact of noisy or unreliable signals from occluded joints, improving training quality.

## Handling Underwater Challenges

The unique underwater challenges (occlusions, poor visibility, distortions) were addressed through three architectural and data choices:

### 1. Visibility Annotation
Visibility settings reduced training noise and improved keypoint accuracy by letting the model not penalize predictions on truly invisible joints.

### 2. Augmentation Strategies
Flipping, rotation, and translation simulated diverse scenarios — helping the model generalize to swimmer poses it hadn't seen exactly.

### 3. Exclusive Underwater Focus
By training **exclusively on underwater data**, the system was optimized for aquatic-specific conditions. Mixing in terrestrial data would have introduced features (above-water lighting, dry-pose anatomy) that don't transfer to underwater scenes.

This combined approach leverages HRNet's inherent strengths while adapting its training to underwater-specific requirements. The resulting model not only detects swimmer poses accurately but also provides a foundation for downstream swim performance analysis.
